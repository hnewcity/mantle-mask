# CPU 与内存优化验证

## 范围与兼容性

本轮优化覆盖配置读取、请求日志、流式观察器与控制台后台请求；不更改 API JSON 结构、配置/SQLite 格式或备份格式。没有连接生产实例测量 CPU/RSS，也没有调用真实 AWS 推理。

- **配置快照**：用显式深拷贝替代 JSON 编解码；推理只复制路由、设置和当前用户。鉴权与快照在同一读锁内完成，撤销/禁用/恢复后新请求立即采用新配置，已有请求仍持有独立快照。完整快照接口保持兼容，映射、切片和可选单价指针均不共享可变存储。
- **日志与指标**：固定容量环形缓冲区替代满容量时的整数组复制。容量变化时保留最新记录、释放旧缓冲区；稳态写入不再分配数组。指标由扫描日志 30 遍改为扫描一次，仍按请求开始时间分桶、按完成顺序展示最新日志。
- **SSE**：按块寻找换行，仅为跨块行进行拼接；心跳空事件不再进入 JSON 解码。只缓存最近一次成功持久化的响应 ID，跳过连续重复绑定，但不跳过 Token 更新、终止状态或错误。保留原始字节转发、CRLF/多行事件、观察大小限制与失败处理。
- **控制台**：仅用户管理页需要全历史汇总；用量页保留自己的筛选查询。轮询在请求完成 15 秒后再次执行，隐藏标签页暂停并取消未完成请求，显示后立即恢复；手动刷新会替换过期请求，离开页面会取消请求。
- **浏览器内存与渲染**：Markdown、日期控件、迁移设置按页面加载。日志每页最多渲染 100 条，搜索仍覆盖全部保留日志，导出包含全部匹配结果而非当前页。

## 本机微基准

环境：WSL2 Linux amd64、Go 1.27.2、AMD Ryzen 5 3450U，Go 可见 2 个逻辑处理器。前后各运行 3 次，取中位数；基准期间不并发运行构建或浏览器测试。基线为 v0.3.1，使用相同 fixture 和基准代码。

| 操作 | 优化前耗时 | 优化后耗时 | 优化前 B/op | 优化后 B/op |
| --- | ---: | ---: | ---: | ---: |
| 完整配置快照 | 14.787 ms | 179.72 μs | 4,021,069 | 258,416 |
| 推理鉴权和路由快照 | 13.721 ms | 69.74 μs | 3,899,822 | 4,688 |
| 满 1,000 条日志后写入 | 96.26 μs | 30.32 ns | 278,528 | 0 |
| 满 10,000 条日志后写入 | 2.493 ms | 33.73 ns | 2,727,936 | 0 |
| 10,000 条日志的指标汇总 | 5.372 ms | 361.86 μs | 7,088 | 3,632 |
| 100 个 SSE chunk 的观察 | 1.057 ms | 434.32 μs | 23,603 | 15,115 |

配置 fixture 为 8 个上游、1,000 个 API Key、1,000 条参考价格，命中最后一个 Key。旧推理路径使用 `AuthenticateSnapshot`，新路径使用 `AuthenticateRoutingSnapshot`；完整快照另外对比同名接口。日志基准先填满缓冲区，指标 fixture 有 10,000 条日志，SSE fixture 为每次观察 100 个约 2 KB 的 Chat chunk。

**这些数字只表示对应函数的耗时和每次调用累计堆分配，不是生产 RSS、HTTP 吞吐量或整机 CPU 降幅。** 日志仍占用配置容量所需的常驻空间，只是消除了每条日志额外复制整个数组的开销。

复现当前实现：

```bash
go test ./internal/config ./internal/gateway -run '^$' \
  -bench 'Benchmark(ConfigSnapshot|Authenticate.*Snapshot|Runtime|Stream)' \
  -benchmem -count=3
```

复现基线：在独立的 v0.3.1 checkout 中复制当前 `internal/config/performance_test.go` 和 `internal/gateway/performance_test.go`，运行同一命令（不复制依赖新接口的 `snapshot_test.go`）。不要在运行中的数据目录操作，也不要并发运行两组基准。

## 前端构建

按需加载前，本轮主入口 JavaScript 为 675.64 kB（gzip 212.68 kB）；拆分后主入口为 约 409.7 kB（gzip 131.2 kB），另有初始共享模块 8.52 kB（gzip 3.28 kB）。Markdown Playground 和用量控件在进入对应页面时才下载；这减少首屏传输与解析工作，不代表浏览器总内存按同样比例下降。

## 回归覆盖

- 配置深拷贝的 JSON 等价、全部可选指针/映射/切片的所有权，以及撤销、禁用、恢复、并发版本一致性。
- 环形日志与简单保留列表的随机对照，扩缩容、零容量、时间桶边界、乱序完成、并发读写和返回值隔离。
- SSE 每个分块边界与逐字节输入、CRLF、多行 JSON、大小限制、多个 Chat choice、响应绑定失败重试和相同 ID 后续用量/失败状态。
- 慢轮询不重叠、隐藏/恢复/卸载、手动刷新替换、错误后的重试；浏览器验证全量历史请求数量以及日志分页、筛选、完整导出和窄屏布局。
- 保留现有用量价格、备份迁移、OpenAI SDK、模型路由和权限测试。

## 保留的持久性边界

没有改 SQLite 同步落盘设置，没有把计量写入改成可能丢失的异步批量写，也没有添加返回过期费用的报表缓存。Responses 首次绑定仍需成功落盘后才继续。

高规模下，Responses 路由文件的全量持久化、SQLite 写入和大范围历史扫描仍可能成为瓶颈。将路由文件改为增量存储涉及恢复、备份和迁移协议，应结合实际负载剖析另行验证，而不是在本轮静默降低可靠性。

本轮验证命令：`go test -race -p 1 ./...`、`go vet ./...`、`npm --prefix web test`、`npm --prefix web run build`、`npm --prefix web run test:e2e`。
